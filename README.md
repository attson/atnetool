# ATNetool

用于网络测试、问题定位与处置验证的桌面诊断工作台。后端基于 Go `net/http/httptrace` 采集 DNS、TCP、TLS、TTFB、总耗时和 Cloudflare `CF-Ray`，支持代理路径识别、直连对照测试与手动代理验证；前端使用原生 HTML/CSS/JavaScript，桌面容器使用 Wails v2。

## 检测范围

- DNS 查询对象、解析 IP 与累计解析耗时
- DNS 深度诊断对照系统解析、Cloudflare/AliDNS UDP 与 Cloudflare/Google DoH，采集 A、AAAA、CNAME、NS、TTL、响应码和 AD 标志，并区分 CDN 调度差异、局部通道阻断与本地重写风险
- 端口与协议检测对用户明确选择的最多 24 个 TCP 端口并发探测，区分开放、拒绝、超时、无路由和不可达，并对常用 HTTP/TLS 端口补充状态码、证书与 ALPN 证据
- TCP 本地/远端连接端点与建连耗时
- 系统代理、手动代理、强制直连和疑似透明代理/VPN
- TLS 协议、加密套件、ALPN、证书主体/签发者/有效期
- HTTP 协议、状态码、重定向链、TTFB、总耗时和响应大小
- Cloudflare `CF-Ray`、节点位置与 `CF-Cache-Status`
- 完整诊断会同时执行最多 15 跳、20 秒的 Traceroute，并预留最多 4 秒补全 GeoIP
- 持续监控对任意现有 HTTP/HTTPS 地址执行最长 30 分钟的小流量采样，统计可用率、P50、P95、Jitter、连续失败、延迟超限事件以及远端 IP/Cloudflare 节点变化；用户主动停止时仍保存已采集证据
- 站点巡检以最多 6 路并发检测一组常用或自定义网站，每站最多读取 4 KiB，归纳 DNS、出口连接、TLS、局部故障与共性高延迟
- Cloudflare IP 优选内置官方 IPv4/IPv6 网段，支持自定义 IP/CIDR、随机抽样或 IPv4 全量测试；先以 TCPing/HTTPing 采集平均延迟、丢包率、状态码和地区码，再对入围节点执行可选的限时下载测速，支持延迟/丢包/速度/地区筛选、CSV 导出、调试错误和 hosts 灰度建议
- 网络基线识别活动接口、地址类型、MTU、默认路由与网关绑定、IPv4/IPv6 公网直连能力，标记 VPN/TUN/虚拟网卡、多默认路由和路由接管风险；同时对照系统 DNS、Cloudflare、AliDNS 与 Google DNS，并联合分析系统代理及常见本地 HTTP/SOCKS5 监听端点
- 路径对照对同一目标并行比较系统代理、强制直连和可选手动代理，统计成功率、TCP/TLS/TTFB/总耗时 P50 与 Jitter，并识别实际相同的连接路径
- 历史记录可导出本地 ZIP 诊断报告包，包含可读摘要、关键指标、分层结论、代理与 Traceroute 证据，以及按模块拆分的脱敏 JSON
- 链路详情支持真实世界地图与原始跳点双视图；地图会自动适配本次路径范围，以带方向的连线呈现节点跳转，并支持按钮/滚轮缩放、拖拽平移和节点详情查看
- 支持亮色、暗色主题并记住当前设备上的主题选择

## 产品模块

- 综合诊断（当前可用）：一次并行执行本地网络、DNS、80/443 端口、HTTP/TLS/Traceroute 和系统/直连/手动代理路径对照，按严重度输出分层结论与治理顺序
- 域名诊断（当前可用）：针对指定域名执行 HTTP、代理和路由联合诊断，定位问题并验证治理效果
- DNS 深度诊断（当前可用）：比较系统 DNS、公共 UDP DNS 与 DoH 的记录和传输可用性，输出保守的异常归因与 DNS 治理动作
- 端口检测（当前可用）：检测指定主机的明确端口及应用层协议证据，不扫描网段，输出端口故障分类与治理动作
- 持续监控（当前可用）：按可配置时长、间隔和阈值观察目标响应，聚合异常时间线与路径变化，不依赖自建服务端，也不将结果表述为宽带速度
- 站点巡检（当前可用）：对内置或自定义网站执行有界小流量检测，实时展示逐站阶段耗时、连接路径和跨站共性结论
- Cloudflare IP 优选（当前可用）：对齐 CloudflareSpeedTest 的候选生成、TCPing/HTTPing、延迟丢包过滤、下载测速、地区与状态码筛选、速度排序和 CSV 输出，并保留当前 DNS 基线、真实域名验证、历史对比与 hosts 灰度建议
- 网络基线（当前可用）：从接口、默认路由、网关绑定、MTU、DNS、公网直连出口和本地代理采集证据，区分协议栈缺失、多出口竞争、VPN/TUN 路由接管与显式代理场景
- 路径对照（当前可用）：以每路径 3 或 5 次、每次最多读取 4 KiB 的采样结果比较可达性和响应质量，输出连接策略治理建议但不修改系统代理
- 治理任务中心（当前可用）：读取最近一次综合诊断与本地历史，统一呈现治理顺序、推荐连接路径、治理前后指标和 CF IP 优选恢复状态；支持按推荐路径复测，普通治理动作只跳转到对应工具，不会静默修改系统网络设置
- 历史报告（当前可用）：在本机查看、对比和复测最近 100 次结果，并将任一记录导出为可直接交付客服或运维的 ZIP 证据包

界面通过顶部 Tab 在上述模块间切换，每次只呈现当前工具及其结果。

## Cloudflare IP 优选边界

Cloudflare IP 优选默认从随客户端发布的官方 IPv4/IPv6 网段生成候选，也可读取用户导入的其他 Cloudflare IP/CIDR。常规模式对每个 IPv4 `/24` 随机抽样一个地址，IPv6 按配置数量随机抽样；“IPv4 全量测试”只在用户显式开启后执行。候选请求强制直连，不继承系统代理；界面同时标记系统代理配置与活动 VPN/TUN 风险。代理线路质量应使用“路径对照”单独验证，因为代理端可能重新解析域名，本机 hosts 或优选 IP 不一定生效。

目标域名为必填项，用于建立当前 DNS 基线、绑定 HTTP Host/TLS SNI，并验证优化是否适用于具体业务。候选扫描开始前会同时检查解析 IP 是否属于 Cloudflare 官方网段，以及响应是否包含 `CF-Ray` 或 Cloudflare 服务标识；两类证据均不存在时不会继续执行 Cloudflare 候选扫描。

TCPing 结果表示本机到候选 IP 的网络层质量，具有一定线路通用性；HTTPing 会进一步使用目标域名的 Host、SNI、路径和状态码验证业务可用性。不同域名的 WAF、证书、缓存、地域规则和回源配置可能不同，因此最终治理结论应以目标域名的 HTTPing 验证为准。结果区以当前 DNS 节点为基线，直接展示推荐 IP 的延迟、丢包和下载速度变化；下载测速开启时，当前 DNS 基线会被强制纳入测速，缺少有效速度基线时不会计算提速比例。

下载测速默认使用 Cloudflare 公共测速地址，也可由用户替换或完全关闭，不要求自建服务端。下载测试会产生实际流量，测速数量、单节点时长和速度下限均可配置。客户端只复制 hosts 建议，不自动修改系统 hosts；Anycast 路径和运营商网络会变化，应用建议前应在目标设备及问题时段复测。

## Traceroute 实现

路由追踪会与 HTTP 诊断在同一次任务中并行执行。Go 使用 `exec.CommandContext` 直接调用系统工具，不经过 shell，也不会拼接可执行命令字符串。Windows 使用系统自带的 `tracert`，macOS 使用 `traceroute`，Linux 优先使用通常无需 root 权限的 `tracepath`，缺少工具时会在界面中明确提示。

Traceroute 反映本机网络栈到目标 IP 的路径，不会展示 HTTP/SOCKS 代理内部的路由；TUN/VPN 仍可能接管探测流量。中间节点显示 `NO REPLY` 通常表示其不响应 ICMP 探测，不等同于链路中断。

地域视图使用随应用打包的 Natural Earth 国家边界底图，并通过 `ipwho.is` 与 `ipinfo.io` 交叉校验公网跳点的城市、网络组织和经纬度，同时采集 PTR 主机名作为辅助信息。相近位置的连续跳点会聚合显示数量，详情中保留完整跳点范围、地址、定位来源和可信度。私网、保留地址和定位失败的跳点不会被强行放到地图上。Cloudflare 目标优先使用 `CF-Ray` 机房代码，Traceroute 未到达目标时以虚线连接最后一个可见节点和已确认的边缘机房。GeoIP 表示网络注册或服务区域，不代表路由器的精确物理位置。

## 输入诊断地址

用户可以在主界面输入域名或完整 URL。只输入域名时，客户端会自动使用 HTTPS，并记住上次填写的地址。

建议使用满足以下条件的地址：

- 由 Cloudflare 代理，以便响应包含 `CF-Ray`
- 无需登录且不包含敏感数据
- 响应体尽可能小，推荐提供专用 `/health` 接口
- 可接受诊断客户端发起的 `GET` 请求

## 代理检测

界面支持三种连接方式：

- 自动代理：优先读取 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY`；Windows 会读取当前用户系统代理，Linux 会读取 GNOME 系统代理及忽略列表
- 绕过代理：本次检测强制直连，不使用显式代理
- 手动代理：支持 HTTP、HTTPS、SOCKS5 和 SOCKS5H 代理地址

结果会标记直连、已使用代理或疑似透明代理/VPN。复制报告时会移除代理 URL 中的用户名和密码。

## 本地历史与对比

应用会在用户配置目录保存最近 100 次综合诊断、域名诊断、DNS 深度诊断、端口检测、持续监控、站点巡检、Cloudflare IP 优选、网络基线或路径对照，历史文件采用版本化结构和原子写入；升级后会自动迁移原先保存在 WebView `localStorage` 中的记录。完整结果不会自动上报到业务服务器；DNS 深度诊断和网络基线会把用户填写的域名提交给界面列出的公共 DNS/DoH 解析器，地域视图会把公网跳点 IP 发送给 `ipwho.is` 和 `ipinfo.io` 查询 GeoIP，私网地址不会发送。可以选择两条同类型记录，对比综合模块状态与服务耗时、DNS 解析器可用性与地址组、端口状态与协议证据、DNS/TCP/TLS/TTFB、持续监控的可用率/P50/P95/Jitter/异常事件/路径变化、巡检通过率、CF IP 候选中位耗时、网络基线中的默认路由/活动接口/VPN-TUN/MTU/DNS/代理监听变化，或路径对照中的推荐路径与分段耗时，也可以沿用历史配置直接复测。

每条历史记录都可以导出为 ZIP 报告包。报告完全在本机生成，不调用上传接口；后端会清除 HTTP/HTTPS/SOCKS 代理中的用户名与密码、URL 查询参数和片段，并递归遮盖 token、Cookie、Authorization、密码、密钥、本机名和网卡硬件地址。公网 IP、DNS 响应与路由跳点会作为排障证据保留，导出前仍应确认报告接收方可信。

## 本地开发

```bash
wails dev
```

Wails 会启动前端热更新服务并生成 Go/JavaScript 绑定。

## 测试与构建

```bash
go test ./...
wails build
```

构建产物位于 `build/bin/`。Windows 生成 `ATNetool.exe`，macOS 生成 `ATNetool.app`。

使用仅提供 `webkit2gtk-4.1` 的新版本 Linux 发行版时，执行：

```bash
wails build -tags webkit2_41
```

## 产品边界

客户端不提供需要自建测速节点、遥测接收端或 iperf 服务端的功能。Cloudflare IP 优选只测试内置的官方网段或用户明确导入的 IP/CIDR，全量 IPv4 测试必须由用户显式开启；其下载结果表示候选 Cloudflare 节点到本机的单连接下载表现，不等同于标准宽带测速。完整结果默认仅保存在本机；GeoIP 查询行为见上文说明。
